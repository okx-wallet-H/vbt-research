# 61 — 订单簿挂单墙：能否替代 K 线支撑阻力

> 日期：2026-09-04（UTC+8 约 12:00，OKX 公共 WebSocket 实时数据）
> 研究 Agent：订单簿研究
> 结论先行：**挂单墙真实存在、可精确识别（top 墙是相邻档位的 100~3500 倍），但它和 K 线支撑阻力是两种东西——距离差一个数量级。墙是盘中微观流动性结构（现价 ±0.05%~1.8%），不是 K 线的日级摆动位（±1%~5%）。能不能"用"，取决于你拿它做的是日内剥头皮，还是日级择时。**

---

## 1. 接入方法（可复制）

端点 `wss://ws.okx.com:8443/ws/v5/public`，订阅 `books` 频道（默认 400 档），无需 key。

```python
# 依赖：websocket-client（环境已有 1.9.0）
import json, time, threading
import websocket

WS_URL = "wss://ws.okx.com:8443/ws/v5/public"
INST_IDS = ["XRP-USDT-SWAP", "DOT-USDT-SWAP", "SOL-USDT-SWAP"]

books = {i: {"bids": {}, "asks": {}} for i in INST_IDS}

def on_message(ws, message):
    if message == "ping":            # OKX 文本 ping/pong 保活
        ws.send("pong"); return
    obj = json.loads(message)
    arg = obj.get("arg", {})
    if arg.get("channel") != "books" or arg.get("instId") not in books:
        return
    action = obj.get("action", "snapshot")   # 第一条=snapshot，之后=update
    b = books[arg["instId"]]
    for d in obj.get("data", []):
        if action == "snapshot":
            b["bids"] = {p: float(sz) for p, sz, *_ in d["bids"]}
            b["asks"] = {p: float(sz) for p, sz, *_ in d["asks"]}
        else:                         # 增量：size==0 表示撤单
            for p, sz, *_ in d.get("bids", []):
                sz = float(sz)
                (b["bids"].pop(p, None) if sz == 0 else b["bids"].__setitem__(p, sz))
            for p, sz, *_ in d.get("asks", []):
                sz = float(sz)
                (b["asks"].pop(p, None) if sz == 0 else b["asks"].__setitem__(p, sz))

def on_open(ws):
    ws.send(json.dumps({"op": "subscribe",
        "args": [{"channel": "books", "instId": i} for i in INST_IDS]}))

ws = websocket.WebSocketApp(WS_URL, on_open=on_open, on_message=on_message)
t = threading.Thread(target=ws.run_forever, kwargs={"ping_interval": 20, "ping_timeout": 10})
t.daemon = True; t.start()
time.sleep(25); ws.close()
# books 里就是三个品种的完整 400 档订单簿
```

要点：
- 第一条 `action=snapshot` 是全量快照，之后 `action=update` 是增量；**update 里 `size==0` 表示该价位撤单**（不是 0 量挂单）。
- 每条消息带 `seqId`/`prevSeqId`（严格生产环境要做 checksum 校验，本实验 25~30s 短抓未做，够用）。
- 完整可跑脚本在 `backtest/orderbook_capture.py`（抓快照）、`backtest/orderbook_stability.py`（抓墙稳定性时间线）。

## 4. 墙的稳定性（30s，每 2s 采样 15 次）

**分两类，这是本次研究最关键的发现：**

1. **DOT / SOL 的墙 = 石头**。30 秒内几乎不动：
   - DOT 支撑墙 0.8738：149,329 → 152,156（15 次采样全程在位，量只微调）；阻力墙 0.8785：151,069 → 152,980。
   - SOL 整数关口 102.00@50,380：**15 次采样一个 tick 都没变**；103.20@17,123 同样纹丝不动。这是真金白银堆着的结构性挂单（大概率机构/做市商/大户）。
2. **XRP 的墙 = 水**。在区间内漂移：支撑墙价位 1.4434 → 1.4444 → 1.4429 → 1.4428（在 ~0.2% 区间内换挡），量 4,594 → 6,357 波动 ±30%。不是固定价位，是一个"墙区"。

含义：**整数关口 + 大单量的墙最可靠**（SOL 102.00、DOT 0.8785），散户挂单堆出来的"墙"会漂移。识别时应优先「整数价位 + 量远超邻域」的墙，而不是单纯看量大。

## 5. 挂单墙 vs K 线支撑阻力

同品种对比（K 线取 4H 近 50 根摆动高低点）：

| 品种 | K线近期阻力（4H 高点） | 订单簿卖墙 | K线近期支撑（4H 低点） | 订单簿买墙 |
|------|------|------|------|------|
| XRP | 1.4839 (+2.3%) | +0.27%~0.49% | 1.4339 (-1.0%) | -0.19%~-0.60% |
| DOT | 0.9016 (+2.85%) | +0.20%~0.47% | 0.8532 (-2.68%) | -0.29%~-0.53% |
| SOL | 107.87 (+3.9%) | +0.15%~0.55% | 99.87 (-3.7%) | -0.50%~-1.66% |

**核心差异：距离差一个数量级。**
- 订单簿墙：现价 **±0.05% ~ 1.8%**（大多 sub-0.6%），是**盘中实时**的、动态移动的。
- K 线 S/R：现价 **±1% ~ 5%**，是**历史摆动极值**、静态的。

两者不是"谁替代谁"的关系，是**两个尺度**：
- K 线 S/R → 日级择时的"关键价位"。
- 订单簿墙 → 日内剥头皮/做市级的"即时流动性边界"。

## 6. 结论

**能不能用订单簿墙判断支撑阻力？分三点：**

1. **可识别性：能，且是确定性的。** 墙量 ÷ 中位档量 = 100~3500 倍，5x 阈值轻松满足，不存在"算不出墙在哪"的问题。DOT 和 SOL 的墙（尤其整数关口）在 30s 内纹丝不动，是真实挂单，不是噪声。

2. **但"墙 = 阻力/支撑"这个映射有致命隐患，30s 观察无法排除：**
   - **Sweep（扫单）**：墙再大，一个足够大的市价单也能瞬间打穿。墙量大只能说明"这里流动性厚"，不能说明"价格会在这里反转"。
   - **Spoof（假挂单）**：大单可能是挂着吓人的，临近成交前撤掉。30s 窗口只能排除"秒级 spoof"，排除不了"挂几分钟后撤"。
   - **磁吸效应**：大墙有时不是挡住价格，而是**吸引**价格去吃掉它（价格朝流动性密集处移动）。支撑墙未必托底。

3. **跟 K 线算的位差多少：差一个数量级（上面第 5 节）。** 所以正确的用法是**分层**，不是二选一：
   - 做**日级震荡套利**（当前项目方向）→ K 线摆动位仍是主信号，订单簿墙离价太近（±0.2%~0.6%），用来当入场位会被正常波动反复扫到。
   - 做**日内**（分钟~小时级）→ 订单簿墙是有效输入，但必须叠加"墙稳定性 + 是否被 sweep"的验证。

**给项目的下一步建议（研究性质，不下单）：**
- 若想真验证"墙是否有效"，需要做**事件研究**：记录价格触碰到某堵墙（如 DOT 0.8785 卖墙、SOL 102.00 买墙）之后 N 分钟内，是反弹还是穿透，统计命中率。这需要挂 WebSocket 跑小时级采集，是下一阶段的事，不是 30s 能下结论的。
- 结论模板：**「大墙 = 真金白银的流动性事实」成立；「大墙 = 价格反转点」未被证明，需事件研究才能验证。**
