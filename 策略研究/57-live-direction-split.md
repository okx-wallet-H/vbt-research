## 3. 多空分化（核心线索，N 太小）

| 方向 | 笔数 | 止盈 | 止盈率 | 累计盈亏 |
|---|---|---|---|---|
| 多 | 10 | 2（LAB/ALLO） | 20% | **-11.91U** |
| 空 | 4 | 3（VANA/MMT/PENDLE） | 75% | **+8.25U** |

- **线索（空单 N=4，待验证）**：空单止盈率 75%、净 +8.25U，远好于多单 20%、净 -11.91U。且空单 3 笔止盈分散在 2 个时段（上午 PENDLE/MMT，下午 VANA），不是同一分钟脉冲的偶然。
- **但统计不成立**：空单 3/4 的 Wilson 95% CI ≈ **[30%, 95%]**，下界已跌破本策略平衡线 37.5%。N=4 撑不起「空优于多」的结论。
- **与回测矛盾，先不下结论**：《50-pattern-study》实测「冲高失败做空」胜率 ~30%（负 EV），而实盘空单 75%。两种可能：① 实盘 N=4 纯运气；② 回测的「做空」与实盘「贴阻力做空」入场条件不同。**这个矛盾本身是值得深挖的点，不是结论。**

### 3.1 多空分化的另一种读法（比「方向」更可能是真因）

上午批（11:42 UTC≈北京）同时开了 7 多 + 2 空，结果**空全胜、多 6/7 全败**。更简洁的解释：**那个时点市场在下行，做空顺风、做多逆风。** 策略是双向的，胜负由行情方向决定，而非「做空这个动作本身有 alpha」。这与 56 号「方向是行情决定的」洞察同源，只是修正为「双向触发」而非「单向逆势」。

## 5. 币种 × 价格（无成交额/杠杆字段，不下结论）

- 数据里只有 `inst/side/pnl/open_px/close_px/close_ts`，**没有成交额、杠杆、持仓量字段**，无法做成交额/流动性分层。
- 价格区间有表面分化：止盈的 5 币价格 0.069~1.97（中高价），止损里有多个超低价币（ATH 0.0047 / PUMP 0.0043 / PEPE 3.7e-6 / BIO 0.0276 / MON 0.0256）。**但这是混淆变量**：这些低价币恰好都是多单，而多单整体胜率就低（20%）。**不下「低价币差」的结论**，除非有纯空单的低价币样本。

### 5.1 PEPE 精度线索（N=1，待验证）

PEPE 是唯一 scratch（-0.1021U，价格只动 -0.03% 就记「止损」）。原因：PEPE 价格 3.665e-6，-3% 止损线 ≈ 3.555e-6，受最小报价单位限制，止损价被四舍五入到 3.664e-6，导致**实际止损点从 -3% 漂移到 -0.03%**。→ **超低价格币（<0.00001）的止损价计算受 tick size 限制，TP/SL 会严重偏离设定值。** 待更多超低价币样本验证。

## 6. 盈亏比结构与平衡线（沿用 56 号口径）

- `result` 的「止盈/止损」= `realizedPnl > 0 ? 止盈 : 止损`，是**盈亏符号不是真 TP/SL 命中**（56 号已标，仍成立）。
- 但用 open_px→close_px 反推：止损基本 -3%、止盈基本 +5%（价），与实盘规则「止盈 +5% / 止损 -3%」吻合 → 除 VANA/PEPE 外，其余 12 笔是标准 TP/SL 形态。
- 盈亏比 = 赢均 4.18U / 亏均 2.73U = **1.53:1** → 平衡线 = 1/(1+1.53) = **39.5%**。
- 实际胜率 35.7%，Wilson 95% CI ≈ **[16.4%, 61.2%]**（n=14），平衡线 39.5% 落在区间内 → **连「是否跌破平衡线」都无法统计确认**。
- 方向性观察：当前 35.7% 略低于平衡线 39.5%，净 -3.66U，与 56 号「5%/3% 比例撑不住这个胜率」的方向一致。

## 7. 结论

**样本够不够：不够。** 14 笔里 9 笔是同一分钟窗口的相关样本，独立市场时刻只有 4 个；空单 N=4、多单 N=10，任何分组都撑不起统计结论。

**值得深挖的方向（按优先级）：**

1. **空单优势的真伪**（最优先）：空 3/4 vs 多 2/10 是当前最强信号，但 N=4 且与回测「冲高失败做空负 EV」矛盾。**需要攒到空单 ≥20 笔**再判断，重点看实盘「贴阻力做空」与回测「冲高失败做空」的入场条件到底差在哪。
2. **多单入场信号在下跌市失效**：上午批 7 多 6 止损，说明「贴支撑做多」信号在下跌市里大面积触发且全败。值得单独查：这批多单的开仓信号是什么、是否该加趋势/regime 过滤（接《33-regime-filter》）。
3. **补 open_ts**：`positions-history` 不返回 uTime，持仓时长算不了，这是时间维度最缺的一块。建议从 OKX orders/fills 反查开仓时间，或 recorder 里开仓时记一笔。
4. **数据源路径核对**：任务给的是 `backtest/output/trade_log.json`，但 `trade_recorder.py` 的 OUT 指向 `_research_repo/实盘/output/trade_log.json`，两处不一致，建议确认哪个是权威，避免下次分析读到旧文件。

## 附：可复跑分析片段

```python
import json, math
log = json.load(open(r"C:\Users\CF\Desktop\VBT研究站\backtest\output\trade_log.json", encoding="utf-8"))
t = log["trades"]
def ci(wins, n):
    p = wins/n; z=1.96
    d = 1 + z*z/n
    c = (p + z*z/(2*n))/d
    h = z*math.sqrt(p*(1-p)/n + z*z/(4*n*n))/d
    return (c-h, c+h)
for side in ("多","空"):
    g = [x for x in t if x["side"]==side]
    w = sum(1 for x in g if x["pnl"]>0)
    lo,hi = ci(w, len(g))
    print(f"{side}: n={len(g)} 止盈={w} 胜率={w/len(g):.0%} 净={sum(x['pnl'] for x in g):+.2f}U 95%CI=[{lo:.0%},{hi:.0%}]")
w = sum(1 for x in t if x["pnl"]>0)
lo,hi = ci(w, len(t))
print(f"全体: n={len(t)} 止盈={w} 胜率={w/len(t):.0%} 净={sum(x['pnl'] for x in t):+.2f}U 95%CI=[{lo:.0%},{hi:.0%}] 平衡线=39.5%")
```
