# 33 — Regime Filter（方向过滤）：顺着市场方向做，能不能挖出真 alpha

> 背景：research/31 钉死「单因子趋势择时是过拟合」（MC 中位数 -6%~-7.5%、正占比 20~42%）；
> research/32 发现「做空对 SOL/DOGE 有 +33~35pp 的结构性下行 alpha，但 naive 无脑双向被 squeeze/whipsaw」，
> 给出下一步候选 = **带方向过滤的做空**。本文落地 regime filter：用慢指标判三态（上行/下行/震荡），
> 只在顺势方向交易，验证「顺着市场方向做」到底能不能把下行 alpha 留住、避开 squeeze。
>
> 全部数字来自 `backtest/output/regime_results.json`，脚本 `backtest/regime.py`（实跑，可复现）。

---

## 一句话结论

**不能。** 慢指标方向过滤在诚实 walk-forward 下依然过拟合：全样本里 ma200 把 SOL 从 +54.9% 刷到 +83.2%，
但 Monte Carlo（250 条随机路径 × 5 种子）中位数直接转负（**-5.29%，0/5 种子为正**）；更关键的是——
**连 naive 双向本身在 SOL 上本已存在的 +5.5% OOS 中位数（5/5 种子为正），都被 regime filter 打没了**。
三个 regime 方法（ma200 / donchian / adx）没有一个通过严格检验，**方向过滤不是答案**。

## 一、方法与三态判定

| 项 | 值 |
|----|----|
| 数据 | OKX USDT 本位永续 4H，BTC/ETH/SOL/DOGE 各 3000 根（2025-04-14 ~ 2026-08-27），复用 `shorting_data.pkl` |
| base 策略 | SMA（fast=20, slow=50）**固定默认参数、零选参**（research/32 的结构性口径） |
| 手续费 | 0.05% 单边 |
| 方向过滤 | regime=UP → 只放行 long、屏蔽 short（离开 UP 当根强制平多）；DOWN → 只放行 short；RANGE → 空仓 |
| regime 参数 | train 段扫网格选参（ma200/donchian `window∈{100,200,300}`；adx `trend∈{20,25,30}×range∈{15,20}`）|

三个 regime 判定（`backtest/regime.py`，全部实跑验证）：

| 方法 | 判定逻辑 | 三态 |
|------|---------|------|
| **ma200** | close vs 200 周期均线：上=UP、下=DOWN | 两态（无震荡） |
| **donchian** | close 破前 N 根最高价=UP、破最低价=DOWN、区间内沿用前态 | 三态 |
| **adx** | ADX>trend=趋势（方向由 +DI/-DI）、<range=震荡、中间滞回沿用前态 | 三态 |

**做空贡献** = 过滤后双向 − 过滤后单向（long-only），衡量做空侧在过滤后还剩多少。

## 六、为什么 regime filter 反而毁了 SOL 的下行 alpha（核心机制）

research/32 的 +33~35pp 下行 alpha 来自 **SMA 20/50 快交叉「尽早」吃满 SOL/DOGE 的下跌段**（死叉即做空）。
而 regime filter 用的是 **慢指标确认**（200MA / ADX / Donchian 200），它要求「下跌被确认了」才放行空单：

- **SOL 的真实路径**（已验证）：133.5 → 248.3（+86% 早盘暴涨）→ 61.6（-75% 崩盘）→ 101.2 收盘。
  200MA 在崩盘前被早盘暴涨拉得很高，price 跌破 200MA 时崩盘已经走完大半——**慢过滤器天然吃不到崩盘的主跌段**。
- 实测（已验证）：naive 做空贡献 +35.1pp → ma200 做空贡献只剩 **+16.1pp**，donchian **-17.8pp**，
  adx **+12.1pp**。做空这口肉被慢确认腰斩甚至转负。
- 反过来 ma200 的 long 侧在 SOL 上吃到早盘暴涨（longonly +67.1%），撑出 +83% 的漂亮全样本——但那是
  **一次性、路径特异**的，MC 随机切分切不到那段，中位数就转负。

**一句话**：做空 alpha 和「慢 regime 确认」在机制上是对立的——前者要快、后者要稳，叠在一起就是
「要么过度过滤（adx，没交易了）、要么滞后确认（ma200，吃不到主跌段）」。

## 七、判定与下一步

### 明确判定

1. **regime filter 没有挖出真 alpha，依然过拟合**。严格检验（MC 中位数正 + 正占比 ≥60% + P25 不深负 + 多种子稳定）
   下，12 个 regime×币 格子 **0 个通过**；全样本的唯一亮点 ma200·SOL（+83%）在 MC 下中位 -5.29%、0/5 种子。
2. **三个 regime 方法没有有效者**：ma200 全样本只在 SOL 上刷分（OOS 转负）、在 BTC/ETH 上帮倒忙；
   donchian 几乎全线更差；adx 唯一贡献是压回撤（BTC 回撤 -36%→-14%），但把做空肉砍光、且过度过滤到分布退化。
3. **意外的正发现**：固定参数 + 双向的 naive·SOL 反而是全实验唯一「5/5 种子正中位数」的配置
   （MC 中位 +5.50%、正占比 60%），但它 P25 -5.15%、CPCV P25 -29.05%，下尾极深，也不是干净 edge。
   这修正了「naive 双向中位数负」的口径——负的是「longonly + 网格选参」，不是「双向 + 固定参数」。

### 值不值得继续

**regime filter 这个方向到此为止，不值得继续调。** 三条理由：
- 机制上，慢方向过滤与「快吃下跌」的下行 alpha 对立，靠调窗口/阈值救不回来（窗口网格 {100,200,300} 已试）。
- 统计上，全样本→MC 的坍塌幅度（ma200·SOL +83%→-5.3%）和 overfit gap（+78pp）和 research/31 完全同构。
- 按 research/31 的 Checklist：「发现过拟合是好事 → 转向下一个 idea」。

**真正值得继续的方向（按价值排序）**：

1. **naive·SOL 的「弱正 + 深尾」能否被风险管理救活**：它 5/5 种子正、但 CPCV P25 -29%。若加一个
   「单段最大回撤止损 / 空头挤压保护」把深尾削掉，可能比 regime filter 更接近真 edge。这是
   「做空有结构性 alpha、但需要的是风险控制而不是方向过滤」的直接推论。
2. **拉长历史**（4H 可回拉到 2021 年）：当前 16 个月是「分化市」，做空 alpha 的区间特异性还没坐实，
   2022 真熊市里做空 + 快交叉是否更值钱，是决定「做空值不值得上」的最后一关。
3. **放弃方向过滤，直接研究「快信号 + 止损」**：research/31+32+33 三连问已经把「参数调优」「方向过滤」
   两条路都证伪，剩下唯一没试的就是「把深尾切掉」的风险管理层。
