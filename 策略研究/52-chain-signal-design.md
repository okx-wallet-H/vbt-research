# 52 — 链上筹码分布择时信号方案（策略一：主流币 · 长期持有）

> 背景：`strategy/playbook.md` 策略一「主流币 · 链上筹码分布择时 + 长期持有」。
> 用户原话（逐字）：①「BTC 这些主流币，根据资金阻力位置，大概能判断出高位在哪里，低位在哪里，
> 要做的就是长期持有，不去管他。」②「不是我的判断，是 Agent 可以看到多少资金被套在哪里。」
> ③「不仅要盯，还要记录，有变化我们就可以快人一步。」
>
> 拆解：数据层（读链上筹码成本分布 + 持续记录快照）→ 检测层（对比快照抓变化：增仓/解套/派发/换手）
> → 判断层（套牢密集区=高位/阻力、筹码地板区=低位）→ 执行层（低位买进、长期持有、不做波段）。
>
> 本方案把上述心法落成 5 个可计算的链上信号，供数据到位后直接照着写验证脚本。
>
> 铁律：每一步数据 + 公式支撑，不拍脑袋。所有参数标注「来源 + 如何用数据定」，凡未验证的一律标「未验证」。

---

## 一句话结论

链上筹码分布的**静态一维图**（每个价位套着多少币）就是「钱套在哪」；它的**连续快照之差**
就是「钱往哪走」。本方案定义 5 个信号：2 个整体盈亏标尺（MVRV / SOPR）+ 1 个分布载体（筹码成本带）
+ 2 个从分布派生的择时信号（高低位 / 快照变化）。**全部未验证**，必须用 BTC 真实 UTXO 快照过
CPCV/Monte Carlo，且对照「buy & hold」基线——因为策略一是长期持有，择时信号必须跑赢拿住不动才有价值。

## 一、数据源与字段

### 1.1 核心数据：UTXO 集（Bitcoin 账本，策略一主战场是 BTC）

MVRV / SOPR / 筹码成本带三个指标的**共同地基**是 BTC 的 UTXO 集：账本上每一个未花费输出（UTXO）
携带一个关键字段——**「最后移动时的价格」**（即该枚币的成本基 cost basis）。

| 字段 | 含义 | 信号用途 |
|------|------|---------|
| `value_u` | UTXO u 的面额（satoshis） | 筹码数量/价值的权重 |
| `created_price_u` | UTXO u 创建（上次被移动）时的币价 = 其成本基 | 判断该币的盈亏、归入成本带 |
| `created_height_u` | UTXO u 创建时区块高度 | 换算成时间 + 持币时长（STH/LTH 分界） |
| `spent_price_i` / `spent_value_i` | 被花费 output 的花费时价格 / 面额 | SOPR 分子分母 |

### 1.2 数据源（含「能回到」与状态，需落地时逐一确认）

| 数据 | 内容 | 来源 | 状态 |
|------|------|------|------|
| UTXO 集快照 | 全网 UTXO + 每个的成本基 | Glassnode / Coin Metrics / CryptoQuant（付费，招牌指标）；免费路径 = 自跑 Bitcoin Core 全节点 `gettxoutsetinfo` + txindex 自算 | **未落地**（需确认用哪家） |
| 花费流（spent outputs） | 每笔花费的创建价/花费价 | 同上（SOPR 需逐块扫花费） | **未落地** |
| onchainos-cli | 链上数据（holder 分布/聚类/token 价格） | 本环境已配 MCP | 偏 EVM/Solana **token 层**，对 BTC UTXO 级成本基指标覆盖**待确认**（大概率不能直接给 realized cap） |

- **明确认知**：MVRV / SOPR / URPD 是 Glassnode 的招牌 BTC 指标，业界标准定义都以 **UTXO 模型** 为准。
  免费能拿的「接近物」是自跑全节点（要 txindex，重建成本高）；onchainos-cli 的 holder 分布是**地址级**
  （谁持有），不是**成本级**（套在哪价位），两者不可混用。
- **ETH 延伸**：ETH 是账户模型，无原生 UTXO 成本基，其 realized cap 需「实体调整」近似（Glassnode 后补的），
  复杂度高、口径不一。**策略一 v1 只做 BTC**，ETH 标 [待定] 后续单独处理。

## 二、五个信号构造

> 参数统一标注：`[待定]` = 数据下来后网格 + Monte Carlo 选，不是拍脑袋；`[数据定]` = 用数据分布直接算。

### 信号 1：MVRV（整体盈亏位置，判断高位还是低位）

**定义**：全网市值 / 全网已实现市值，衡量「整体浮盈还是浮亏」。

```
Market Cap      MC(t) = P(t) × Σ_u value_u                    # 现价 × 流通量
Realized Cap    RC(t) = Σ_u ( value_u × created_price_u )     # 每枚币按成本基计价 = 全网持仓总成本
MVRV(t) = MC(t) / RC(t)
```

- **是什么**：MVRV > 1 全网平均浮盈，< 1 全网平均浮亏。越高越接近顶部（大量获利盘有抛压动机），
  越低越接近底部（大量亏损盘惜售/麻木）。
- **凭什么可能有用**：它直接回答用户「高位在哪里、低位在哪里」的**整体**尺度——不是某个价位，而是
  全网的盈亏温度计。历史顶/底通常对应 MVRV 的极端区。
- **参数**：
  - 分桶粒度：UTXO 精确求和 vs 按日快照近似 `[待定]`（UTXO 全量是精确值，每日快照够用）
  - 高/低位分界：MVRV 的**历史分位**（如 P90 = 高位区，P10 = 低位区）`[数据定]`——用自身历史 MVRV
    序列算分位，**不抄**行业经验阈值（>3.7 / <1 是别的样本的结论，不可外推）
  - 变体：free-float MVRV（剔除交易所托管/长期丢失币）`[待定]`
- **状态**：未验证。

### 信号 2：SOPR（花费产出利润率，抛压/派发检测）

**定义**：被花费的币「现在卖出的总价 / 创建时的总价」，衡量**卖出的人**平均在获利还是割肉。

```
对每笔花费 i：SOPR_i = spent_price_i / created_price_i      # >1 盈利卖，<1 亏损卖
价值加权聚合：SOPR(t) = Σ_i( spent_value_i × spent_price_i ) / Σ_i( spent_value_i × created_price_i )
```

- **是什么**：SOPR = 1 是盈亏平衡线（关键支撑/阻力）。>1 且持续 = 获利盘在兑现；<1 = 割肉盘在投降。
- **凭什么可能有用**：这是「派发/抛压」最直接的探测器——**卖币的人是赚是亏、在哪个价位卖**，
  直接对应心法里的「派发（见顶）」和「解套（抛压释放）」。
- **关键变体**（选哪个 `[待定]`，均未验证）：
  - `aSOPR`：剔除寿命 < 1h 的 output（同一钱包内部转账，非真实换手），降噪
  - `STH-SOPR` / `LTH-SOPR`：按持币时长（155 天分界）分开看短期/长期持有者的卖出盈亏
- **参数**：
  - 聚合窗口（日/周）`[待定]`
  - 是否剔短寿命（SOPR vs aSOPR）`[待定]`
  - STH/LTH 分界（155 天是 Glassnode 标准，建议 `[数据定]` 重算）`[待定]`
  - 「派发」判定阈值：高位区间 SOPR 持续 >1 的天数 / 幅度 `[数据定]`
- **状态**：未验证。

### 信号 3：筹码成本带（cost basis distribution，套牢密集区识别的载体）

**定义**：把价格轴切成 N 个价位带 bin，每个 bin 统计「成本基落在此价位」的筹码总量。这就是
「每个价位套着多少资金/筹码」的直接度量（业界名 URPD = UTXO Realized Price Distribution）。

```
对价位带 b = [p_b, p_b + Δp)：
D(b, t) = Σ_{ u : created_price_u ∈ b } value_u          # 该价位带上的筹码量（按数量或按 value）
```

- **是什么**：一张「成本分布直方图」，横轴价格、纵轴筹码量。价格上方的高峰 = 被套的密集筹码；
  价格下方的高峰 = 低成本持仓的密集筹码。
- **凭什么可能有用**：这是**静态分布**的载体（钱套在哪）。前两个信号是「整体温度」，
  这个才是「结构地图」——套牢密集区、筹码地板区都从它身上读。
- **参数**：
  - bin 宽度 Δp `[数据定]`：按当前价格 ±X% 范围内自适应（对数 bin 或固定 N=1000 个 bin），
    使「峰」能分辨
  - 计价单位：按 BTC 数量 vs 按 USD 价值 `[待定]`（USD 价值更能代表「多少资金」）
  - 是否实体调整（合并同一实体的 UTXO，防钱包拆分干扰）`[待定]`
  - 快照频率（每天一张）`[数据定]`
- **状态**：未验证。

### 信号 4：套牢密集区 / 筹码地板区 → 高低位

**从信号 3 的分布 D(b,t) 派生**，给定当前价格 P(t)：

```
套牢区（被套）= { b : b > P(t) }     获利区（浮盈）= { b : b < P(t) }
套牢密集区（阻力/高位）= 套牢区内筹码密度最高的价位簇
筹码地板区（支撑/低位）= 获利区内筹码密度最高的价位簇
```

**转成可交易的「高低位」信号**（核心是相对位置，不是绝对峰）：

```
position(t) = Σ_{ b < P(t) } D(b,t) / Σ_all D(b,t)      # 成本低于现价的筹码占比 ∈ [0,1]
高位 = position(t) > 上分位 [数据定]
低位 = position(t) < 下分位 [数据定]
```

- **是什么 / 凭什么可能有用**：
  - `position(t)` 高 = 绝大多数筹码已获利 → 上方抛压重 → **高位**；
  - `position(t)` 低 = 绝大多数筹码被套 → 下方惜售支撑、割肉盘枯竭 → **低位**。
  - 套牢密集区（上方峰）= 解套抛压的阻力位；筹码地板区（下方峰）= 惜售支撑位。
    两者是 `position(t)` 这个「一维标尺」在**结构**上的注脚。
- **参数**：
  - 「显著峰」判定：密度 > 背景密度 × k `[待定]`
  - 高/低位分位阈值 `[数据定]`（用 position 自身历史分位）
  - 只看距 P(t) 的 ±X% 带宽 `[待定]`（太远的旧筹码对当前择时无意义）
- **状态**：未验证。

### 信号 5：快照变化（增仓 / 解套 / 派发 / 换手）

**定义**：信号 3 连续快照的**逐带差分**。链上机制的关键——一笔 UTXO 被花费，其成本基「消失」；
新 UTXO 创建，成本基「写成当前价」。所以 ΔD 的本质是**成本基重写的位置转移**。

```
ΔD(b, t, Δt) = D(b, t) − D(b, t − Δt)          # 正=该带筹码变密（有人在此建仓/接盘），负=变稀（在此卖币）
```

**四类变化 = 对 ΔD 按价位带分类判定**（这是「持续记录 + 抓变化」的可执行形式）：

| 变化 | 检测公式（示意） | 含义 | 对应心法 |
|------|----------------|------|---------|
| 增仓（吸筹/见底） | 低位带（地板区附近）`ΔD > 0` 显著 | 成本基净流入低位 = 有人在低位建仓 | 见底 |
| 解套（抛压释放/突破） | 套牢密集区 `ΔD < 0` 显著 | 被套筹码在成本价附近被花费（解套卖出），套牢区消肿 | 抛压释放 |
| 派发（见顶） | 高位带（现价上方近端）`ΔD > 0` 显著 | 成本基净流入高位 = 主力把筹码卖给高位接盘者 | 见顶 |
| 换手（趋势转折） | 分布重心显著移动 `μ(t) = Σ_b b·D(b,t) / Σ_b D(b,t)`，`Δμ` 显著 | 筹码在某价位密集换手、重心平移 = 新一轮起点/终点 | 趋势转折 |

- **凭什么可能有用**：这是用户「不仅要盯，还要记录，有变化快人一步」的直接落地——
  **静态分布告诉你套在哪，动态差分告诉你钱正在往哪走**，后者才是「快人一步」的信息增量。
- **稳健化度量**（供验证用，别直接用裸 ΔD）：
  - 分带净流：`netflow_low(t) = Σ_{b∈低位带} ΔD(b)`，`netflow_high(t) = Σ_{b∈高位带} ΔD(b)`
  - 各带 z-score：`z_b = ΔD(b) / σ(ΔD(b) 历史)` `[数据定]`
  - **解套的方向性**必须结合价格：涨到成本价解套（利好，抛压释放→变支撑）vs 割肉解套（利空），
    二者 ΔD 都是负，需用 SOPR 或价格方向二次区分 `[待定]`
- **参数**：
  - 快照间隔 Δt（日/周）`[待定]`
  - 低位带/高位带的划分（相对 P(t) 的 ±x%）`[数据定]`
  - 「显著」阈值（z-score 或 k×背景）`[数据定]`
- **状态**：未验证。

## 三、数据预处理

链上数据是「每天一张 UTXO 快照」，量级远小于订单流（每日 ~百万 UTXO 级，可离线预处理），流水线：

1. 拉 UTXO 集快照（每日）→ 逐 UTXO 归入价位带 → 得 `D(b, t)` 成本分布矩阵（价格 × 日期）。
2. 由同一快照直接算 `MC(t)`、`RC(t)`（→ MVRV）、`position(t)`；由花费流算 SOPR。
3. 差分相邻快照 → `ΔD(b, t)` → 分带净流 + z-score → 四类变化布尔标记。
4. 产出宽表喂 VBT：
   `{日期, close, MVRV, SOPR, position, 套牢密集区价位, 地板区价位, netflow_low, netflow_high, 增仓/解套/派发/换手布尔}`。
5. 择时落地为布尔 entry/exit → `vbt.Portfolio.from_signals`（长期持有：entry = 低位，exit = 高位，或只做
   entry 不做波段——与心法「不做波段」对齐，波段维度作为对照实验）。

## 四、验证方案（沿用 research/30~43 的尺子，不降低标准）

1. **样本**：BTC 链上历史（UTXO 快照能回到的年限，取决于数据源，目标 ≥ 2 个完整牛熊周期）。
   注意：链上指标是**日频**，样本点比 K 线少一个量级，CPCV 折叠数要适配（不能照搬 4H 的 250 路径参数）。
2. **回测**：信号 → 布尔 entry（低位）/exit（高位）→ `vbt.Portfolio.from_signals`，fees=0.1%（现货档），
   只做多（策略一是长期持有，不做空）。
3. **判定尺子（CPCV / Monte Carlo，路径数+种子按日频数据重定）**：
   - MC 中位数为正 + 正收益占比 >50% + 选参跑赢随机参 + 多种子稳定 → 才算 edge。
4. **对照（策略一专属，比 45 号多这一条）**：择时信号必须**跑赢 buy & hold 基线**（买入持有不动）。
   因为心法本身就是「长期持有，不去管他」——如果 MVRV 择时跑不赢拿住不动，说明「判断高位低位」
   这件事在 BTC 上并不产生超额，诚实记录。
5. **诚实标注**：若 5 个信号全不通过，如实记录「链上筹码分布维度在 BTC 上也无易得的普适 alpha」，
   继续换下一数据源/下一层（订单簿深度 / taker 流已在 45 号）。

## 五、执行顺序

1. **先定数据源**：确认能否拿到 BTC UTXO 级快照（Glassnode/Coin Metrics 付费，或自跑全节点），
   这是全部 5 个信号的共同地基，没地基一切空转。onchainos-cli 大概率不够（token 层 ≠ 成本级），需确认。
2. 数据到位 → 验**信号 1（MVRV）+ 信号 4（position 高低位）**——信息量最大、实现最简单，
   直接回答「高位/低位」。
3. 信号 3（成本带）+ 信号 5（快照变化）——依赖分布矩阵，是「套牢密集区/地板区」和「抓变化」的载体。
4. 信号 2（SOPR）——依赖花费流，单独拉，做「派发/解套」的方向性确认。
5. 每个信号单独过 CPCV/Monte Carlo + buy & hold 对照，通过才进入组合。
